🛡️ Acesso Remoto a Servidores via SSH

Conceito-Chave: O SSH (Secure Shell) opera na porta padrão 22/TCP e estabelece um túnel criptografado seguro para administração remota, eliminando os riscos de interceptação inerentes a protocolos legados sem criptografia (como Telnet e rlogin).

1. Anatomia das Chaves e Arquivos Essenciais

  • ~/.ssh/: Diretório pessoal que armazena credenciais e histórico de conexões do usuário.
  • ~/.ssh/id_ed25519 (ou id_rsa): Chave Privada — Segredo absoluto. Deve permanecer exclusivamente na máquina de origem com permissões restritas (0600).
  • ~/.ssh/id_ed25519.pub: Chave Pública — Pode ser compartilhada livremente com os servidores remotos.
  • ~/.ssh/authorized_keys: [No Servidor] Lista as chaves públicas que possuem autorização para autenticar na conta.
  • ~/.ssh/known_hosts: [No Cliente] Armazena a assinatura (fingerprint) dos servidores já acessados, prevenindo ataques de Man-in-the-Middle (MitM).
  • /etc/ssh/sshd_config: Arquivo mestre de configuração do daemon OpenSSH no servidor.

2. Comandos Práticos de Operação

# 1. Gerar novo par de chaves moderno usando curva elíptica (Ed25519)
ssh-keygen -t ed25519 -C "admin@secvault.local"

# 2. Copiar chave pública para o servidor remoto de forma automatizada
ssh-copy-id -i ~/.ssh/id_ed25519.pub usuario@ip_do_servidor

# 3. Conectar utilizando autenticação baseada em chave
ssh -i ~/.ssh/id_ed25519 usuario@ip_do_servidor

# Conexão em porta não-padrão:
ssh -p 2222 usuario@ip_do_servidor

Transferência Segura de Arquivos:

# SCP - Enviar arquivo local -> remoto
scp -P 22 script.sh usuario@ip_do_servidor:/tmp/

# SCP - Baixar arquivo remoto -> local
scp usuario@ip_do_servidor:/var/log/auth.log ./

# SFTP - Sessão interativa segura para navegação e transferência
sftp usuario@ip_do_servidor

3. Hardening & Boas Práticas Defensivas

Configurações recomendadas no arquivo /etc/ssh/sshd_config do servidor:

Diretiva Valor Seguro Impacto de Segurança
Port 2222 (ou alta) Reduz ruído de varreduras automatizadas e bots na internet.
PermitRootLogin no Impede login direto como root; exige rastreabilidade via conta comum + sudo.
PasswordAuthentication no Neutraliza ataques de força bruta/dicionário ao exigir chaves criptográficas.
PubkeyAuthentication yes Habilita autenticação segura baseada em criptografia assimétrica.
MaxAuthTries 3 Encerra a conexão após 3 tentativas inválidas consecutivas.
AllowUsers secuser admin Lista estrita (allowlist) de usuários autorizados a conectar via SSH.
⚠️ Regra de Ouro em Produção: Antes de reiniciar o serviço SSH com systemctl restart sshd, sempre valide a sintaxe do arquivo de configuração usando sudo sshd -t. Nunca feche a sessão atual antes de abrir uma nova janela de terminal e confirmar que o novo login funciona!
